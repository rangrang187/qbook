# qbook Sprint Backlog（迭代任务文档）

文档版本：0.5｜日期：2026-10-23｜状态：V0～V3 已实现并完成自动化验收；V4～V5 未开始

本文件按提供的 Sprint Backlog 模板编写，将 qbook 的需求和技术设计拆为 **V0–V5 六个版本、25 个任务**。它回答每版交付什么、先做什么、怎样判断完成；逐步编码步骤、具体命令和文件修改顺序由对应的 `Implementation_Plan(Vn).md` 承接。实现状态依据实际验收更新，结果见本地 [V0 验收记录](releases/V0.md)、[V1 验收记录](releases/V1.md)、[V2 验收记录](releases/V2.md) 和 [V3 验收记录](releases/V3.md)（不上传 GitHub）。

## 1. Project Overview（项目开发总览）

### 1.1 项目开发目标

qbook 参考 nqbook 重新开发，使用自己的项目名称和已有 qlib 基础库。服务接收市场行情，按交易品种维护订单簿，周期生成最优买卖一档快照，将事件和快照保存为 Parquet 文件，并通过只读页面展示运行状态。订单簿记录外部市场变化，**不会主动撮合买卖订单**。

完整开发过程需要留下可复验的证据：需求为什么这样规定、接口怎样配合、固定输入得到什么结果、发生失败时怎样退出、性能实验测了什么，以及最终如何在记录的环境中重新运行。代码存在、进程没有退出、日志显示启动，都不能单独证明功能完成。

### 1.4 版本划分原则

1. 每版形成可运行或可验证的完整能力。V1 能直接调用订单簿验证状态；V3 才能声明网络事件已经正常保存为文件。
2. 先验证业务，再接入长期工作循环，随后连接真实文件和页面。早期核心构建不被 Arrow、ZMQ 或 Node 的安装要求阻塞。
3. 正确性和错误处理随功能落地。首次引入并发就验证停止和故障解除等待，不留到“最终测试版”。
4. 指标数据类型属于前期共享基础，发布线程和浏览器属于后期功能。这样前期阶段不会依赖空指标类或伪造计数。
5. V0–V5 是能力里程碑，不等于六周或六个固定时长的 Sprint；具体日程依据实际进度再确定。
6. 本计划不包含真实交易、主动撮合、自动补历史、跨重启恢复或公网产品化。真实行情接入仍受 OI-02、OI-03 约束。

### 1.5 任务拆分原则

一个任务交付可观察的行为，例如“改单后数量和同价顺序正确”，同时包含必要的边界和验证，不按每个成员变量、私有函数拆任务。跨任务共用的夹具、错误控制和指标类型只维护一份；后续任务在已有基础上扩展。

任务优先级沿用需求：**P0** 是建立核心正确性和可靠运行所必需的任务；**P1** 是监控、性能证据及最终完整交付中的任务。P1 不表示可以省略：FR-01～FR-17 的完整目标仍需要 V4、V5。前置依赖优先于优先级，同一人的默认执行顺序按任务编号推进；具备条件后才考虑并行。

任务状态统一使用“未开始、进行中、阻塞、待验收、已完成”。只有实际运行验证并留下结果后才能标已完成。计划中的验收标准写“应当如何”，完成记录写“实际发生了什么”，二者不能混写。

### 1.6 全局完成标准（Definition of Done）

Definition of Done 指一项工作可以标为完成时必须满足的条件；它不等于代码已经写完。

1. 本任务范围内的行为已实现，与需求和规格一致；未覆盖的范围清楚列出，没有通过空实现或静默吞错凑齐接口。
2. 当前目标能够在记录的工具链和固定依赖下构建；实际发现并运行相关测试，没有测试时必须明确失败，不能把空跑当通过。
3. 正常、关键边界及本任务引入的失败路径已验证；结果以可观察状态、输出和退出情况判断，不只看日志。
4. 跨线程对象的所有权、停止顺序和资源生命周期符合规格；正常保存只承诺成功进入 FeedQueue 的事件，不能扩大为所有网络发送消息。
5. 文档、接口、配置和测试夹具与实现同步。中文说明、英文标识符；qlib 问题在对应库处理后更新依赖，不在 qbook 复制一套容器。
6. 在 `docs/releases/Vn.md` 中记录任务或版本的实际环境、代码/依赖标识、命令、测试数量及结果、输出位置和剩余问题；没有执行的项目写“未执行”，不填“通过”。
7. 性能结论有相同条件下的实测证据；未定阈值只允许交付基线，不宣称达到吞吐或延迟目标。
8. Git 提交、推送按用户当前授权执行。提交哈希只有实际存在时才登记；提交或推送不是替代验收的证据。

### 2.1 版本列表

|---|---|---|---|---|

### 2.2 各版本的功能范围

| 版本 | 本版建立的能力 | 明确延后的能力 |
|---|---|---|
| V0 | 工程与共享约定；独立验证配置和控制/指标基础。 | 业务处理、实际接收、写文件、监控页面。 |
| V1 | 单线程普通调用中的订单簿行为；多实例隔离与容器移动测试。 | BookThread 的实时分发与周期调度，网络和持久化。 |
| V2 | 接入处理链与周期快照，测试记录收集器验证输出。 | 生产 Parquet 写入与正式采集服务；测试收集器不是产品输出。 |
| V3 | 网络→建簿→文件的三阶段核心服务。 | MetricsThread 网络发布与 UI；已有阶段计数照常更新。 |
| V4 | 完整运行监控及只读页面，补齐 FR-13～FR-17 的对外验收。 | 长期指标数据库、账号系统、真实交易。 |
| V5 | 实验、证据支持的改进、受控环境完整复验。 | 无依据的“极致性能”改造、未经确认的生产环境扩展。 |

功能的首次实现与最终验收可能不在同一版。例如 V1 能验证重复新增不改变数量，但“该事件仍写入订单文件”必须在 V3 验证；V2 测试消费者收到记录也不能替代 Parquet 可读性检查。第 4.1 节列出全部需求和验收的对应任务。

### 2.3 各版本的依赖关系

默认按 V0、V1、V2、V3、V4、V5 顺序交付。V1 使用 V0 的依赖和公共数据；V2 使用 V1 的业务接口和 V0 的控制/指标；V3 把 V2 的记录输出接到真实写入器；V4 使用各阶段已维护的指标；V5 对已经具备完整行为的系统测量和复验。

V3 的同步 ParquetWriter 可以在共享记录契约稳定后提前独立实现，V4 的页面也可以先用固定指标样本开发，但这些不改变版本完成门槛：V3 必须通过真实处理链验收，V4 必须接上真实发布端。提前编写的独立组件不能让依赖版本自动变成已完成。

### 2.4 版本开发顺序与优先级

| 顺序 | 优先级与推进方式 | 开始前需要满足的条件 |
|---|---|---|
| V0 | P0；优先建立可验证基础。 | 已有需求、规格和 V0 实现计划；核对实际工作区。 |
| V1 | P0；一次完成一个业务行为及其边界。 | V0 基础验收通过，qlib 接入和公共契约明确。 |
| V2 | P0；接入与停止协议同时推进。 | V1 核心结果可信；固定输入协议和实际 ZMQ 依赖。 |
| V3 | P0；数据完整性与错误退出属于同一交付。 | V2 链路可测；Arrow/Parquet 版本与导出目标已核对。 |
| V4 | P1；基础指标不能反过来依赖页面。 | V3 核心服务可运行；固定 Node/UI 依赖与指标 ABI。 |
| V5 | 实验与分析为 P1，最终完整复验为 P0；先定义实验再测量，有证据才改实现。 | V4 全部功能通过；性能实验环境已记录，绝对目标依 OI-04 决定。 |

| 里程碑 | 可检查的结果 | 不应误认为完成的情况 |

## 3. Version Details（版本详细计划）

本章按模板为每个版本重复“版本概述、任务总览、任务详细说明、版本级验收”。为了避免六次出现相同章节号，V0–V5 分别使用 3.1–3.6；每项任务保留模板要求的 12 项说明，版本验收保留 7 项。任务状态按实际结果更新；V3 已完成验收，V4～V5 仍为未开始。

### 3.1 V0 工程、配置与共享基础

#### 3.1.1 Version Overview（版本概述）

1. **版本编号与名称：** V0，工程、配置与共享基础。
2. **版本开发目标：** 让开发者在明确的工具链和依赖版本下编译真实测试，读入有效配置，并获得后续线程共用的数据、错误状态和指标基础。
3. **本版本交付的核心能力：** 可复验的构建入口、已固定的 qlib 数据契约、通过校验的 Config，以及可独立验证的 RunControl 和 Metric/Metrics。
4. **本版本范围内的功能：** 文档归位、依赖版本记录、公共类型、ABI 检查、配置加载和边界校验、首个致命故障记录、原子指标及值快照。
5. **本版本范围外的功能：** 不实现订单更新、网络接收、工作阶段、Parquet、UI 或性能优化；不以空函数、空类和只有打印输出的程序冒充可运行服务。
6. **前置版本与依赖条件：** 无前置代码版本；开始前确认工作区、当前文档、可访问的 qlib 来源和目标编译环境。负责人及工期待确认，当前不能用历史 qlib 测试结果代替 qbook 构建结果。
7. **对应文档：** `requirement.md` 第 6、8 章及 FR-01；`specs.md` 第 3 章、4.1、4.5.2.1～4.5.2.2、5.4；`Implementation_Plan(V0).md` 已编写，本次按四项任务实施。

### 4.3 尚未实现的功能与限制

V0 已提供构建、公共契约、配置和故障/指标基础。V1 已完成同步 Orderbook 核心及异常、移动验证。V2 的协议、Feed/Book、周期快照与测试链路已实现并验收。V3 已完成五类 Parquet、Writer、正式服务入口及文件链路验收。指标发布、UI 与性能实验属于 V4～V5，仍未开始。

即使 V0–V5 全部完成，以下边界仍存在：只维护市场订单簿、不撮合；快照每侧一档；只保留当前运行内状态；没有自动补历史、断线重同步、跨重启恢复、跨文件统一回放顺序或在线订单查询。ZMQ 发布订阅不提供端到端不丢消息的保证；文件关闭成功不等于断电安全；UI 是运行观察工具，不是审计系统。

真实行情接入和性能门槛分别受 OI-02/03、OI-04 限制。默认本机、受控环境的完整演示可以独立进行，但不能被描述为已经验证真实交易所兼容、生产高可用或公网多租户安全。

V3 固定包的部分依赖查找配置包含系统路径，protoc 和运行程序还需要解析本地传递动态库。依赖接入模块使用真实查找目标，在配置时为 protoc 设置并恢复库搜索环境，并为运行目标设置可传递的库搜索路径。完整构建和测试已验证这些路径；性能结论仍留待 V5。

### 6.5 下一版本的调整事项

V3 已完成本版验收，V4～V5 保持未开始。每版复盘只把已经得到证据的事项带入下一版：例如接口变化会影响谁、尚未关闭的错误由哪个任务承担、哪些等待或资源问题值得测量。没有证据的优化想法先记录为候选，不自动扩展版本。
